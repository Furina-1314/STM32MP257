# Salacia_Terminal 优化开发提示词

你是一名资深 Windows C++/Qt、TCP/UDP 网络通信、实时数据可视化与工业控制 GUI 工程师。请在现有项目 `Salacia_Terminal` 上进行增量优化，不要另起炉灶，不要无依据重写已经可用的模块。

## 一、项目背景

- 项目名称：`Salacia_Terminal`
- 运行平台：Windows。
- 对端设备：搭载 STM32MP257DAK 的正点原子 `ATK-DLMP257B`，Windows 终端只与其 A35/Linux 侧网络服务交互。
- 项目现状：初步架构已基本搭建完成，本任务是在现有代码上优化。
- UI 设计库：位于 `E:\STM32MP257\Code\FluentUIStyle-3.0\FluentUIStyle-3.0` 的 `FluentUIStyle`。开始 UI 工作前必须确认真实路径、版本、许可证、接入方式和示例工程，不得自行替换为其他 Fluent UI 库。
- 配置文件：必须继续使用项目现有的 `config.ini`，不得新建第二套运行配置来源。
- 参考文档：`ROV_A35_M33_Control_Protocol_v1.0.md`。该文档只作为命令名称、设备数量、值域和 `stop/safe/emergency/horizontal` 业务语义的参考；它描述的 A35↔M33/RPMsg 行为不属于本任务实现范围，也不能直接当作 Windows↔A35 的 TCP wire format。

## 二、严格范围边界

本任务只允许修改 Windows 侧 `Salacia_Terminal`：

- Windows TCP 客户端的连接、发送、接收、分帧、编码、解码和重连；
- Windows UDP 视频接收与 GUI 视图的必要适配，但不改变现有推流配置和行为；
- Windows 侧传感器数据模型、3D 姿态显示、控制交互、告警、日志和配置读取；
- Windows 侧通信函数注册表和 UI 到网络报文的映射；
- Windows 侧单元测试、GUI 测试及用于测试的 mock A35 server。

明确不在本任务范围内：

- 不修改、生成或建议提交 A35/Linux 服务端代码；
- 不实现 A35 侧传感器采集、数据聚合、命令分发或安全处理；
- 不修改 `/dev/ttyRPMSG0`、OpenAMP、RPMsg 或 A35↔M33 协议；
- 不修改、生成或建议提交 M33/FreeRTOS 固件及任何 M 核行为；
- 不实现姿态控制、推进器微调、舵机驱动、DYP-RD 驱动或电池采样；
- 不替 A35/M33 决定收到命令后如何驱动硬件；
- 不因为 Windows 端需求缺少接口，就擅自扩展板端协议。

所有板端能力均视为外部接口。若 Windows↔A35 TCP 接口文档不完整，必须在 `vibeplan.md` 中列出缺失字段、假设和待对端确认项；可以实现 Windows codec 接口、mock server 和候选协议草案，但不得把草案当成已经可用的板端能力，也不得修改板端代码来迎合草案。

## 三、需求优先级与术语

冲突处理优先级：

1. 本提示词中的最新需求和范围边界；
2. 已确认的 Windows↔A35 TCP/UDP 接口约定；
3. `ROV_A35_M33_Control_Protocol_v1.0.md` 中与 Windows UI 有关的业务语义；
4. 现有 `Salacia_Terminal` 的已验证行为；
5. 旧注释、旧配置和未经验证的假设。

Windows 端必须区分：

- `stop`：正常停止命令；Windows 仅负责发送、等待响应并显示状态。
- `emergency`：受控紧急上浮命令；Windows 仅负责发送、等待响应并显示状态。
- `estop`：一级紧急停机。Windows 使用一个独立 TCP 应用层报文，一次携带 10 路舵机和 6 路推进器的全部零值，不拆成 16 条普通命令；它必须与 `stop`、`emergency` 使用不同 Function ID、不同编码入口和不同 UI 状态。
- `safe on/off`：安全模式开关状态。
- `horizontal on/off`：姿态/水平控制模式开关。Windows 不实现姿态算法，只发送模式或统一基准值，并显示 A35 返回的状态。

上述描述只约束 Windows 端报文构造和 GUI 行为，不对 A35/M33 的内部执行方式作要求。若 A35 当前尚不支持 `estop` 专用报文或相关 ACK，必须作为外部依赖报告，不能在本项目中实现板端支持。

## 八、Windows↔A35 TCP 客户端

### 8.1 数据方向

Windows 端处理：

1. A35→Windows：100 Hz 传感器汇总报文；
2. Windows→A35：单路舵机控制，每控制一台使用一个独立应用层报文；
3. Windows→A35：单路推进器控制，每控制一台使用一个独立应用层报文；
4. Windows→A35：单帧 `estop`，同时携带 10 路舵机和 6 路推进器零值；
5. Windows→A35：系统、安全、模式、查询及其他已注册指令；
6. A35→Windows：ACK、数据响应、状态变化、主动事件和告警。

### 8.2 严格按既有接口实现

- 先从现有代码和接口文档确认 Windows↔A35 wire format，不得直接套用 A35↔M33 的 ASCII/RPMsg 格式。
- 如果 wire format 已存在，保持兼容，只修复 Windows 端分帧、解析、线程和错误处理。
- 如果接口缺失，不得直接认定候选协议已被 A35 支持；先在 `vibeplan.md` 列出需要 A35 团队确认的字段。
- Windows codec 必须正确处理 TCP 半包、粘包、逐字节分片、连续多帧、非法长度、错误版本、未知 Function ID、断线和重连。
- 禁止发送裸 C/C++ struct 内存镜像；使用既有序列化规则并明确字节序、字段宽度和长度。
- 请求 Sequence、响应匹配、超时和迟到响应处理遵循既有接口；若接口尚未规定，将其列为待确认项。
- 重连后重新握手/查询权威状态；不自动重放旧舵机、推进器或模式命令。
- 启用 `TCP_NODELAY` 与否、队列容量、超时、重连等全部由 `config.ini` 控制。
- GUI 主线程不得阻塞等待网络或 ACK。

### 8.3 Windows 侧通信函数注册表

所有 Windows↔A35 通信函数必须进入统一注册表，禁止在控件和网络类中散落 Function ID、命令字符串或巨型 `switch/if-else`。

每个 Windows 侧表项至少包含：

- Function ID/外部命令标识；
- 名称、方向和类别；
- 请求/响应载荷类型与版本；
- Windows 编码函数或解码函数；
- 长度、类型、枚举和值域校验；
- Windows 发送入口或接收后分发回调；
- 关联 ViewModel/状态更新类型；
- 是否需要 ACK、超时、优先级；
- 错误码到 Windows 告警的映射；
- 对端能力缺失时的 Windows 降级行为。

Windows 接收流程：字节流缓存→提取完整帧→校验→按 Function ID 查表→解码为强类型数据→投递 Model/ViewModel。Windows 发送流程：UI 意图→集中权限校验→按函数表查找→强类型编码→发送队列→ACK/超时更新。

函数表至少覆盖：连接/握手/心跳（若对端支持）、传感器汇总、单舵机、单推进器、6 路统一基准值、`estop`、`stop`、`emergency`、`safe on/off`、`horizontal on/off`、`ask`、`ver`、`status`、`help`、servo/propeller get/set、sensor 查询、ACK/错误、状态事件和告警事件。

函数表只描述 Windows 的编码、发送、接收和 UI 分发；不得包含 A35 本地处理函数、RPMsg 模板、M33 任务或硬件调用。

### 8.4 低延迟和发送策略

- 紧急停机和紧急上浮使用最高发送优先级，不等待普通控制队列长期排空。
- 所有队列有配置化容量和溢出策略，禁止无限增长。
- 滑条拖动采用 `config.ini` 中的可配置限频；每个实际发出的普通控制值仍是独立报文，松开滑条或输入确认时立即发送最终值。
- 不合并不同设备的普通手动控制；只有 `horizontal on` 的统一基准值和 `estop` 按需求使用多设备单帧。
- 超时后普通控制不得盲目自动重发；显示“状态未知”并在接口支持时查询当前值。

## 九、传感器接收和显示

Windows 接收 A35 汇总后显示：

1. 温湿度：温度、湿度；
2. MPU6500：`ax/ay/az/gx/gy/gz`，以及现有 3D 姿态模块使用的姿态数据；
3. 电压：原始总电压、按 4S 锂电池换算的电量百分比；
4. 测距模块 `DYP-RD`：至前方障碍物的距离。

### 9.1 100 Hz 的含义

- Windows 期望接收 100 Hz 汇总报文，即约每 10 ms 一帧；Windows 不负责也不规定各传感器在 A35/M33 侧的物理采样频率。
- Windows 按报文提供的 Sequence、时间戳、有效位、错误码或数据年龄显示新鲜度；接口未提供这些字段时记录为待对端确认项。
- 不用 0 冒充未就绪、超时、断线或解析失败；有效零值必须能与无效状态区分。
- 网络线程将强类型快照线程安全地交给数据模型。底层可按 100 Hz 接收，文本 UI 按 `config.ini` 中较合适的频率刷新。
- 3D 姿态渲染频率保持现状，具体值从现有 `config.ini` 读取或迁入其中；不得因 100 Hz 网络数据擅自改变。

### 9.2 DYP-RD

- 名称统一为 `DYP-RD`，不要再写成 DYP、DYP-L08 或其他型号。
- 距离的 wire unit、无效值、量程和错误码必须依据 Windows↔A35 接口确认。
- Windows 在数据模型中统一换算为显示单位；单位、精度、告警阈值、过期阈值和量程全部来自 `config.ini`。
- 显示正常值、过近 Warning、危险距离 Error、超量程、未就绪、超时和断线状态。

### 9.3 4S 锂电池电量

- `config.ini` 中 `cell_count` 固定配置为 4，Windows 显示总电压和电量百分比。
- “4S 锂电池”仍不足以唯一确定化学体系和准确 SOC 曲线；不得在源码中硬编码简单线性公式、满充电压或截止电压。
- 在 `config.ini` 中配置电池化学类型、总电压/SOC 分段曲线、滤波、滞回、低电量阈值和严重低电量阈值；未确认化学体系或曲线时明确显示“待标定”，保留原始总电压。
- SOC 输出限制在 0%～100%，曲线单调，异常跳变按配置滤波；任何换算异常形成告警而不是显示伪造的 0%。

## 十、操作逻辑和 Windows UI 状态

使用集中式状态模型，至少分别建模：连接状态、协议握手状态、A35 在线状态、`safe`、`horizontal`、`estop`、`emergency`、请求中、故障/降级。控件可用性由统一权限函数计算，不让多个控件各自保存互相覆盖的布尔值。

| 状态 | 10 路舵机逐路控制 | 6 路推进器逐路控制 | 单一基准转速滑条 | 紧急停机 | 紧急上浮 |
|---|---:|---:|---:|---:|---:|
| 普通手动 | 可用 | 可用 | 隐藏/禁用 | 可用 | 可用 |
| `horizontal on` 且非 `safe` | 置灰禁用 | 隐藏/置灰 | 可用 | 可用 | 可用 |
| `safe on` | 置灰禁用 | 置灰禁用 | 置灰禁用 | 可用 | 可用 |
| `estop` 已确认 | 置灰禁用 | 置灰禁用 | 置灰禁用 | 显示已触发 | 按对端状态显示 |
| `emergency` 已确认 | 置灰禁用 | 置灰禁用 | 置灰禁用 | 可用 | 显示进行中 |
| 断线/状态未知 | 置灰禁用 | 置灰禁用 | 置灰禁用 | 显示无法下发 | 显示无法下发 |

- `horizontal on` 时隐藏/禁用 6 路逐路推进器控件，只保留一条“基准转速”滑条。Windows 通过一个已注册函数将 6 路相同基准值放进一个报文发送，不做姿态算法或逐路微调。
- `safe on` 时所有普通舵机、逐路推进器和统一基准值均禁用，并显示“安全模式已开启”。
- `horizontal on` 显示“姿态控制已开启”。
- 模式以 A35 ACK/状态为准：发送后显示“请求中”，成功后切换，失败/超时后恢复权威值或显示未知。
- 被拒绝的命令恢复控件到最近确认值，并显示原因。
- `estop` 只发送一个独立报文，载荷一次包含 10 路舵机零值和 6 路推进器零值。发送、ACK、失败、超时均有明显反馈；没有 ACK 时不能声称停机已成功。
- `emergency` 与 `estop` 的按钮、Function ID、状态、文案和日志严格分离。
- 紧急状态反馈持续显示，不被普通 Info 覆盖；解除/复位只调用已确认的对端函数，不自行假定板端已解除。

## 十一、FluentUIStyle GUI 重构

### 11.1 布局

- 3D 姿态：沿用现有轴方向、坐标系、零位、单位、滤波和渲染频率，使用相同录制数据验证重构前后轴不交换、方向不反转。

- 舵机：10 条竖直滑条；上方显示当前设定值，下方为输入框；处理空值、非法字符、小数、越界、粘贴、滚轮、失焦；区分目标值、已发送值和 A35 确认值。

## 十二、异常处理

- GUI 主线程不得阻塞执行网络、日志、文件读取或等待 ACK。
- 网络断开时禁用普通控制，清空/失效旧发送项，重连后不重放危险指令。
- 分别显示“TCP 已连接”“协议可用/A35 在线”“遥测正常”“视频正常”，不要用一个绿色圆点概括全部状态。
- 校验所有输入和载荷的长度、类型、枚举、范围、NaN/Inf、版本和 Sequence。
- 拒绝超长帧，限制缓存增长；解析错误时按既有协议安全重同步或断线重连。
- 资源生命周期明确，窗口关闭或切换连接时正确停止线程、定时器和 socket。
- 错误码统一映射为用户文案，同时保留技术详情。
- 配置错误、DYP-RD 数据异常、4S 电池数据异常、ACK 超时和网络异常均进入告警中心。
