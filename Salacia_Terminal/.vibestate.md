- RTP/H264 over UDP 单播 → `192.168.137.1:5000`（Windows ICS 有线 NAT，主机地址）
- **两种分辨率格式：1920×1080（主要传输格式）与 1280×720**；1080p@12fps/4Mbps、720p@30fps/3Mbps（接收侧渲染组件已做分辨率动态切换）
- 动态 PT=96（H264/90000），MTU 1400，`aggregate-mode=zero-latency`
- SPS/PPS 每 1s 带内重发 → 迟入接收端 ≤1s 自动同步（无需 RTSP）；关键帧间隔 1s

**执行机构控制（Phase 6 定稿）：** SSH 通道 CLI `pwm <id> <us>`（id 1-10 舵机 0~180°→[500,2500]us；id 11-16 推进器 ±100%→[1100,1900]us 中位 1500；退出码 0 为成功）

## 7. VibeCoding 协作协议

1. **渐进式输出**：每轮仅针对一个类（.h + .cpp）或一个配置文件，标注完整相对路径；
2. **强制确认**：每轮输出后停顿询问「请在本地编译上述代码，是否遇到报错？」，收到「编译通过」或解决全部报错前不进入下一模块；
3. **状态同步**：每完成一个阶段更新本文件并请确认；
4. **红线不可破**：GBK 字符集、C++17、.ini 参数解耦（禁硬编码）、禁裸指针（除第三方 C 库边界）、网络输入边界校验、智能指针强制；
5. **工业级多线程规范（v1.1 起生效，全部并发代码强制遵循）**：
   - 禁止重写 `QThread::run()` 执行常驻任务；一律 Worker-Object 模式（QObject 工作类 + `moveToThread()` + 事件循环）；
   - UI 隔离：非 GUI 线程严禁触碰 QWidget/QML；跨线程 UI 更新必须信号槽且显式 `Qt::QueuedConnection`；
   - GUI 主线程禁止阻塞 I/O 与耗时计算（waitForReadyRead/Sleep/同步模型加载）；
   - GStreamer 总线/探测器回调向 Qt 侧投递必须 `Qt::QueuedConnection` 或 `QMetaObject::invokeMethod`，严禁回调内直接调 UI；
   - UDP/SSH 等 I/O 独立 QThread，事件驱动异步；
   - 高频视频帧 → 无锁 RingBuffer；低频共享状态（传感器/姿态）用 `std::shared_mutex` 读写锁或 `std::atomic<T>`，禁粗粒度 mutex；跨线程高频结构 `alignas(64)` 缓存行对齐防伪共享；
   - 安全退出（逆序 RAII）：先停网络接收 → `requestInterruption()` + `wait()` 停推理/视频线程 → 最后释放 GPU/ONNX 上下文；严禁后台线程运行期间析构其引用的对象（DataManager 等）。
